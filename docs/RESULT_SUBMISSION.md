# 结果提交与检查

每个任务、种子和运行应使用唯一run ID。保留实际成功、失败和未运行状态；重复执行同一数据来源的同一配置是复现记录，不是新的独立数据集。一个run缺少必要训练臂时不应包装为全部完成。

## 输出与内容

完整运行应包含`RUN_MANIFEST.json`、`METRICS.json`、`PREDICTIONS.csv`、`COST.json`、`ENVIRONMENT.json`、`VERIFY_REPORT.json`和`README.md`，以及执行器生成的逐臂成员、权重、状态和日志。未运行或失败时保留实际生成的状态、成本与日志，不为凑齐文件编造指标或逐条预测。具体字段以`experiments/community/schemas/`及执行器实际输出为准。使用JSON/CSV等可检查格式；不把任意pickle文件作为默认交换格式。

运行清单应绑定任务ID、种子、所用Git提交、协议与配置摘要、数据文件和成员摘要、方法及必要训练臂、实际状态和结果文件SHA-256。环境与成本记录Python和依赖版本、操作系统、可观测硬件、线程与内存上限、训练样本数量、实际耗时和可观测资源峰值；不可观察或不适用的字段保持UNKNOWN/NOT_APPLICABLE，不推断GPU费用。自愿提供的GitHub用户名可以作为署名线索，不要求记录个人姓名、私有路径和机器用户名。

逐条评价须能与冻结评价成员关联，用于重算分类Accuracy、Macro-F1、LogLoss，或回归MAE、RMSE、R²；目标指标和效用增量按相同任务、模型、预算和评价条件解释。当前标准执行器不计算二分类AUROC，记为NOT_EVALUATED；若另行提供该指标，校验器可按约定数据条件核对，不能因未填写而冒称算过。数据选择成员、受控来源修改比例和证据覆盖与训练收益分别报告。受控修改检测不能被写成自然标签错误事实认证。

## 本地检查和提交

先运行`python scripts/experiments/verify_result.py --result path/to/run-directory --data-root ../community-data --output ../verification-report.json`；将占位路径换成实际目录，输出报告使用未存在的路径。自动检查可复核格式、输入/配置摘要、成员隔离、预测和可重算指标；它不能证明计算确实在声称的机器执行，也不自动授予科研接受状态。检查失败要保留，不修改结果回避问题。

在对应Issue记录任务、种子、环境概要、是否改动协议、运行状态、实际错误、完整结果的安全存储位置、SHA-256和保留期限。小型且允许公开的结果索引可经审核放入仓库；大文件使用经维护者同意的构建产物或其他经过授权的存储，不直接提交到主分支。外部下载地址不得包含私密令牌；如果分享链接会泄露身份或数据，先与维护者选择私密交付方式。保留期限应由提供者和维护者在提交前明确，不能假设第三方存储永久有效。

PR使用仓库模板，不在PR中粘贴个人信息、绝密资料或未经授权的数据。仓库自动化以最小权限运行，外部PR不应获得私密令牌或触发受信任的自托管机器。执行结果验收时，应使用维护者信任的基线版本校验器，不以提交方可修改的校验器自我认证。
