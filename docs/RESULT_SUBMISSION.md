# Windows 结果打包、回帖与可选PR

普通贡献者先按对应Issue或 docs/EXPERIMENT_RUNBOOK.md 完成认领、运行和打包。每个任务的三个种子共用一个结果父目录；seed_run_index.csv 记录seed、run_id、实际状态与独立复算。预检或运行失败立即停止，保留已生成的run和错误，不为了凑成功自动重试。

运行清单、指标、预测、成本、环境、自动校验报告及逐臂结果保存在各run目录。失败运行只保留实际产生的内容，不能伪造缺失指标。额外的独立复算报告在仓库外 checks 文件夹，不放进run目录；否则会破坏已冻结的文件成员清单。Issue中的打包代码将同一任务的 results、checks 和 seed_run_index.csv 打入新ZIP，并输出ZIP的SHA-256；数据根目录、虚拟环境、源码和内部材料不打包。

将ZIP拖入对应Issue，填写每个seed的run_id、成功或失败、退出码、自动和独立复算状态、环境概要、是否变更协议、ZIP SHA-256及保存期限。若GitHub附件大小不允许，请先与维护者商定其他可用存储与保留期限；不公开个人联系方式、私有路径、凭据或带令牌的链接。Issue附件不会自动触发结果CI。REPRODUCED只是给定范围内的数值复算，SCIENTIFICALLY_ACCEPTED需要维护者独立审核，不能由CI单独给出。

## 以后如何提交结果PR

当前主分支尚未合入可信校验器，请先通过Issue附件提交结果，不要假装主分支已经能够自动接收。待维护者确认主分支已包含可信校验器、批准结果公开并告知目标分支后，才考虑PR：

1. 在GitHub网页将目标仓库Fork到自己的账号，再按维护者指定的当前协作分支创建结果分支。
2. 通过seed_run_index.csv确认选定的run_id；仅使用完整运行且本地独立复算为REPRODUCED的run。失败或不完整的结果继续通过Issue报告，不冒充成功。
3. 将该run目录原样放入 experiments/community/results/submissions/运行的run_id/。不要更改或删减run内的README、日志、JSON或其他文件；不要加入原始数据、虚拟环境、ZIP或外部checks。每个PR最多4个新增或变更run目录。
4. 向维护者确认的协作分支发起PR；正文注明任务、seed、run_id、固定执行提交、环境概要、协议是否改动、复算结果、异常和先前ZIP SHA-256。
5. 维护者使用可信基线校验器和独立复核决定是否接受。CI绿色不证明执行者身份、原始事实真实性或科学结论成立。

在任何公开分享前，如发现日志或run内其他文件含敏感信息，不要修改后上传；先暂停公开，在Issue仅报告概况，并与维护者商定处理方式。
